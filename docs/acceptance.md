# FactLens · 验收用例和实测记录

日期均为 2026 年，北京时间。浏览器测试使用[公网前端](https://factlens-dn7.pages.dev/)，公网接口位于 `https://factlens.pythonanywhere.com`。下面的结果针对给出的输入和测试时点；新请求可能取回不同资料。

## 本地复测

在仓库根目录启动前后端后，可将同样的输入发送给本地 `http://127.0.0.1:8000/api/check`。夜间公网入口接收超长输入，而仓库 FastAPI 在 2000 字之后返回 400。复测时分别记录端点、HTTP 状态和报告内容。

11 月 8 日，我们复测了本地诊断版。16 项后端测试和 7 项前端状态测试全部通过，前端生产构建成功。测试模拟模型服务的成功、超时、鉴权错误和无效返回，检查处理结果、页面提示以及日志是否对应。线上某次调用是否成功，仍需查看该次请求的服务端记录。

| 复测内容 | 运行位置和命令 |
| --- | --- |
| 后端诊断 | 在本地诊断版的 `factlens-backend` 下激活虚拟环境，执行 `python -m unittest discover -s tests`。 |
| 前端状态 | 在本地诊断版仓库根目录执行 `node --test tests/llm-status.test.mjs`。 |
| 前端构建 | 在仓库根目录安装依赖后，执行 `npm run build`。 |

## 后续验收顺序

1. 给报告和历史记录绑定提交时的原文。取得 A 的报告后编辑输入框、复制报告，核对两处仍引用 A。
2. 同步线上入口的长度校验。在测试环境提交 2000 和 2001 字，分别检查正常进入处理和拒绝处理。
3. 在部署环境验证拆解与判定两阶段诊断。用单次请求编号对照响应与后端日志，确认密钥和输入原文不会出现在日志中。
4. 用以上复合句、同名词条与缺少出处的消息复测证据质量，逐项记录来源是否直接支持对应断言，再检验总标签。
